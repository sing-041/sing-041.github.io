WSL 安装与管理

配套笔记：[[Linux 入门实战]]（进系统后怎么干活）、[[WSL开发最佳实战]]（日常开发最佳实践）、[[WSL 命令速查]]（命令速查表）、[[Ubuntu 开发环境配置]]（常用工具配置配置）

这篇只讲 在 Windows 端（PowerShell / CMD）管理 WSL 本身：怎么装、怎么日常操作、怎么搬到 D 盘。这里所有命令都在 Windows 的终端里敲，不是在 Linux 里面。

1 概念速览

先理清几个词，后面所有命令才有意义。

  • WSL：Windows Subsystem for Linux。它不是虚拟机、也不是双系统，而是让你在 Windows 上原生跑一个 Linux。装好后能直接用 bash、apt、gcc、python 这些 Linux 工具。
  • 发行版（Distribution）：具体的某个 Linux，比如 Ubuntu-24.04。一台电脑可以同时装多个发行版，互不影响。
  • 默认用户：进入 WSL 时自动登录的账号。不设置的话默认是 root（最高权限，容易误操作），建议装好后改成普通用户。
  • .vhdx 虚拟磁盘：一个发行版的所有文件，实际打包存在 Windows 上的一个 ext4.vhdx 文件里。这就是为什么”迁移 WSL”本质上是搬动这个磁盘文件。
  • /mnt 挂载：在 WSL 里，Windows 磁盘被挂在 /mnt/ 下。/mnt/d/ 就是 Windows 的 D 盘，/mnt/d/code 对应 D:\<path>。
  • WSL1 vs WSL2：现在一律用 WSL2（性能更好、兼容性更高）。

性能提示（官方建议）：用 Linux 工具处理的文件，放在 WSL 内部（如 ~/project）最快；用 Windows 工具处理的，放在 Windows 盘。跨系统访问（在 /mnt/d 里跑 Linux 编译）会明显变慢。

（这段话不知道是什么意思来的，直接按照 [[WSL开发最佳实战]]）

2 安装

按顺序走完六步即可。

2.1 开启 Windows 功能（前置）

第一次用 WSL，需要先在系统里打开「适用于 Linux 的 Windows 子系统」和「虚拟机平台」两个功能。

路径：控制面板 → 程序 → 启用或关闭 Windows 功能，勾选这两项后重启。

  • 说明：新版 Windows 用下面的 wsl --install 通常会自动帮你开启；如果安装报错，再回来手动勾选这一步。

2.2 更新 WSL 内核

  • 作用：把 WSL 本体和 Linux 内核更新到最新版。
  • 何时用：安装前先跑一次，避免因内核太旧导致发行版装不上。

2.3 把默认版本设为 WSL2

  • 作用：之后新装的发行版默认使用 WSL2。
  • 说明：只需设一次。2 就是 WSL2，几乎不用 WSL1。

2.4 安装发行版

  • 作用：下载并安装名为 Ubuntu-24.04 的发行版。
  • 参数：
    • -d Ubuntu-24.04：指定要装的发行版。用 wsl -l -o 可查看官方提供的所有可选发行版。
    • --location "D:\software\WSL\ubuntu-24"：指定安装到哪个目录（即 .vhdx 存放位置）。加上这个就能直接装到 D 盘，省去日后迁移；不加则默认装在 C 盘。
  • 说明：装完会自动启动该发行版并进入下一步建用户。

2.5 创建并设置默认用户

某些发行版安装后不会自动引导创建用户，需要手动操作。

2.5.1 以 root 身份进入 WSL

  • 作用：以 root 超级管理员身份进入指定发行版。
  • 参数：
    • -d Ubuntu-24.04：指定发行版名称。
    • -u root：以 root 用户身份登录。

2.5.2 创建普通用户

  • 作用：创建一个普通用户并自动创建家目录。
  • 参数：
    • -m：同时创建用户的家目录（/home/用户名）。
    • -s /bin/bash：指定默认 Shell 为 bash。

2.5.3 设置用户密码

  • 作用：为新建用户设置登录密码。
  • 说明：输入密码时屏幕不显示任何字符，正常打完回车即可。这个密码就是以后 sudo 要输入的密码。

3 迁移到 D 盘

WSL 默认装在 C 盘，用久了占空间。迁移的本质是：把发行版导出成一个 .tar 包 → 删掉原来的 → 在 D 盘重新导入。三步走。

前提：先 wsl --shutdown 关闭所有 WSL，再开始迁移。

3.1 第 1 步 导出为 tar 包

  • 作用：把指定发行版的全部内容打包成一个 .tar 文件（备份）。
  • 参数：
    • Ubuntu-20.04：要导出的发行版名。
    • D:\software\WSL\tar\ubuntu-20.04.tar：导出文件的保存路径（目录需提前存在）。

3.2 第 2 步 注销原发行版

  • 作用：删除 C 盘上的原发行版，腾出空间。
  • 说明：因为第 1 步已经导出备份，这里删掉是安全的。⚠️ 但务必确认上一步的 .tar 已生成成功再执行。

3.3 第 3 步 导入到 D 盘

  • 作用：用第 1 步的 tar 包，在 D 盘重建发行版。
  • 参数（三个位置参数，顺序固定）：
    1. Ubuntu-20.04：导入后的发行版名（可沿用原名）。
    2. D:\software\WSL\ubuntu：安装目录，新的 .vhdx 会放在这里。
    3. D:\software\WSL\tar\ubuntu-20.04.tar：数据来源，即第 1 步导出的 tar 包。
    • --version 2：使用 WSL2。

3.4 迁移后的两个善后

  • 默认用户会变回 root：导入的发行版默认用 root 登录，需要重新设默认用户。
  • 想确认 vhdx 在哪：在 Windows 资源管理器里搜索 ext4.vhdx 即可定位某个发行版的实际磁盘文件。

4 常见坑 & FAQ

  • 占位符怎么填：教程里常见 <DistributionName> / <InstallLocation> / <ExportFilePath>，分别是「发行版名」「安装目录」「tar 文件路径」。<> 是占位符，实际输入时要连同尖括号一起替换掉。
  • VSCode 连 WSL 只能连默认发行版：VSCode 的 WSL 远程默认连接默认发行版。装了多个时，先 wsl --set-default <名字> 把目标设为默认，再用 VSCode 连。
  • wsl --unregister 到底删不删文件：删。它会永久删除该发行版的 .vhdx 和全部内容，迁移/卸载前请先 --export 备份。
  • 路径用哪种斜杠：在 Windows 终端里写 Windows 路径用反斜杠 \；进了 WSL 内部访问 Windows 盘用 /mnt/d/...。
