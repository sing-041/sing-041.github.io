现在的 AI 发展到什么地步了？豆包？龙虾？OR MORE？

现在的 AI 发展到什么地步了？豆包？龙虾？OR MORE？

标题党了哈，这篇文章是“深入不一定深入，浅出一定浅出”的【浅出】系列第一篇，主要内容是用最通俗易懂的语言聊一下什么是 Agent。

我用最直接，最不绕弯子的方式告诉你：Agent = LLM + Harness。

什么是 LLM？

LLM （Large Language Model）大语言模型.

大多数人对 AI 的印象，可能还停留在 豆包、DeepSeek 这类工具上——你问它一个问题，它给你一段回答。这种一问一答的交互方式，确实是目前最常见的 AI 使用方式。

如果你开始用，或者已经在用豆包、DS 了，那么恭喜你，这是所有人学习 AI，接触 AI 的第一步，我也将用豆包这类产品和大家解释什么是 LLM。

LLM 到底是什么？这里给一个百度百科的解释：

大语言模型（英语：Large Language Model，简称 LLM）是指使用大量文本数据训练的深度学习模型，使得该模型可以生成自然语言文本或理解语言文本的含义。

其实是一个很抽象的东西，但是我们可以这样理解。

你点开豆包，创建一个新对话，不要打开任何功能，包括联网搜索，记忆等等，然后开始你们的对话。

这个就是一个 LLM 的调用，它不调用任何工具，包括搜索工具，图片识别工具等等，直接理解你的语言，然后回答你。就像是一个只会说话和思考的机器。

是的，LLM 本身是没有记忆的，我们的每一次问题都是孤立的问题，它只会思考你现在说的，不会记得你之前说的任何东西，至于为什么豆包看起来好像有记忆？—— 豆包不是一个单纯的 LLM。

豆包现在不只是有记忆，还可以做很多事情，联网搜索，生成文档。如果你用过 Claude Code、Codex、或者龙虾，你会发现 AI 甚至可以操控你的电脑，这些能力，并不是大模型（LLM）本身具备的，都是需要额外的“装备”来实现——这就是我们接下来要讲的 Harness。

什么是 Harness？

Harness 的英文本意是”缰绳”。你可以这样理解：LLM 是一匹马，你得安上缰绳才能骑。Harness 就是那根缰绳——**它让 LLM 从一个”只能聊天的大脑”变成一个”能干活的 Agent”**。

Harness 主要包含三个模块：

  • 工具模块
  • 记忆模块
  • 规划模块

工具模块：Agent 的”手”

工具模块让 Agent 能动手做事。比如你让 AI 帮你提取一张图片里的文字，它就会去调用 OCR 工具来完成。

工具模块的核心有两个：

  • Function Call：这个是 Agent 的元能力，如果一个 AI 工具它有 Function Call 就是一个单纯的 LLM，至少也算是一个建议版本的 Agent；
  • MCP（Model Context Protocol）：一套标准化的工具接口协议，让不同的工具可以统一接入，不需要每个工具都单独适配。

MCP

MCP 是一个协议（公认的标准），我们熟悉的协议有 USB 协议。我们先来说说 USB 协议的作用吧。

如果没有 USB 协议，你想要电脑连接鼠标，你可能需要研究如何接线，或者每一台电脑都提供一个专用的键盘，电脑厂商自己研发协议、接口，这样的后果是，每一个牌子的电脑上连接键盘的接口都不一样，每一牌子的连接线也不一样。它们家的电脑就只能用它们家的键盘。如果我想要买键盘，同一个款式，可能的出几十种规格，不同规则本身没有什么区别，但是如果你买错了，就用不了。为什么？因为插不上啊。

之前的 Agent 开发遇到的情况差不多也是这样，你需要为每一个工具实现 Function Call（天气，数据库，读取文件…），这会导致，接入一个新的工具成本非常高，你需要为它专门写一个 Function Call。

直到 Anthropy 发布了 MCP 协议。协议的做法是：我们分为两个角色，一个必须在Agent内（Client），一个由外部提供（Server），Server负责定义工具，Client 只需要问Server有什么工具就行。简单来说，之前Function Call是由Agent实现的，但是现在让数据源去实现，我们Agent成为一个伸手党。

这样就方便多啦，如果需要新一个天气tool，也只需要修改 MCP Server。

MCP协议的终极理想是不再需要写任何工具，所有工具都由MCP server 提供，但现实是很多工具还没有MCP server，所以该自己写还得自己写。

记忆模块：Agent 的”记性”

豆包、GPT 这些产品都是有记忆的，但那是因为它们不是纯粹的 LLM。纯粹的 LLM 是没有任何记忆的——你跟它说一句，它回一句，然后什么都不记得了。

如果你有调用过 LLM 的 API 就会发现，它真的什么都不记。那记忆是怎么实现的？原理其实很简单：你让它记住什么，就把什么东西发给它。

举个例子：你在一次会话里跟 AI 对话了三次。当你说第四次的时候，框架会把前三次的对话内容和你第四次的话一起打包发给 LLM。LLM 看到的是一整段上下文，所以它”好像”记住了之前的对话。

记忆还分两种：

  • 短期记忆：只存在于当前对话，对话结束就没了。
  • 长期记忆：跨对话保存，原理类似，也是把历史信息打包发给 LLM。

当然，LLM 每次能接收的内容是有上限的（上下文窗口）。如果超了怎么办？那就得压缩——把内容精简，只保留最关键的信息。

规划模块：Agent 的”脑子”

规划模块是 Agent 和普通 LLM 对话最直观的区别。

举个例子：你跟豆包说——

“帮我写一篇文章。先给我一个初稿，然后审核一遍，审核完了给我优化版本，最后再给我终稿。”

豆包会在一次回复里把初稿、审核意见、优化版、终稿全部给你。它没有”分步执行”的概念，你说什么它就一股脑全做了。

但如果你跟 Claude Code 这样的 AI Agent 说同样的话，它的行为完全不同：

  1. 它先把需求发给 LLM，LLM 写出初稿，返回给你；
  2. 问你：”初稿在这里，有什么修改意见？”
  3. 它把你的反馈和初稿一起发给 LLM，LLM 给出优化版本；
  4. 再问你：”优化版在这里，还有要改的吗？”
  5. 你确认后，LLM 给出终稿。

一步一步来，每一步都跟你确认。 这就是规划模块的作用——它让 Agent 不再是一次性输出，而是像一个真正的工作伙伴一样，分步骤、有节奏地完成任务。

Skill：Agent 的”技能包”

Skill 是什么？简单说，它就是一个可以复用的技能包。

我们先从最基础的理解开始。一个最简单的 Skill，其实就是一段代码。为什么要发明 Skill 这个东西？原因很简单：如果你反复在用同一段代码、同一个流程，为什么不把它封装起来，下次直接调用呢？

所以最基础的 Skill 有两种形式：

  • 一段描述：告诉 Agent “遇到这种情况你应该怎么做”。
  • 一套步骤：Step 1 做什么，Step 2 做什么，Step 3 做什么——写死的流程，Agent 照着走就行。

比如你经常让 AI 帮你写周报，那你就可以把”写周报”封装成一个 Skill：先收集本周工作记录，再按模板整理，最后润色输出。下次你只需要说”帮我写周报”，Agent 就直接调用这个 Skill，不用你每次重新描述流程。

Anthropic 也为 Claude 实现了专门的 Skill 工具，让 Agent 可以方便地注册和调用这些预定义好的能力。

Workflow：人定流程 vs AI 定计划

讲 Workflow 之前，我们先回顾一下 Agent 的工作模式。

Agent 模式下，你给 AI 一个任务，AI 自己分析、自己制定计划、自己执行。这是我们在前面讲规划模块时说的——计划是 AI 定的。

Workflow 则相反。它是一个自动化的过程，但流程是人定的。

打个比方：你跟 AI 说”每次处理客户投诉，就按这个流程来——第一步记录问题，第二步分类，第三步生成回复模板，第四步发送”。这就是一个 Workflow，AI 不需要自己思考怎么做，照着你定好的步骤执行就行。

Workflow vs Agent 模式：核心区别在哪？

控制权。

Workflow Agent 模式
谁定计划 人 AI
灵活度 低，按固定流程走 高，AI 随机应变
Token 消耗 省，不需要反复思考 费，AI 要不断分析和决策
产出稳定性 稳定，同样的流程同样的结果 不稳定，同样的话问十次可能十个答案

简单说：Workflow 像工厂流水线，稳定高效但死板；Agent 模式像自由发挥的艺术家，灵活但不可控。

实际使用中，两者不是二选一，而是配合使用——用 Workflow 保证核心流程的稳定性，用 Agent 模式处理需要灵活判断的部分。
