Linux 入门实战

前置阅读：[[WSL 安装与管理]]（先装好 WSL）

这篇不讲命令大全，而是帮你建立 Linux 的心智模型：为什么有用户权限、软件包怎么管、文件该放哪。

1 WSL vs 虚拟机：为什么选 WSL

既然要跑 Linux，为什么不直接装虚拟机（VMware、VirtualBox）？

1.1 资源管理方式的区别

方面 虚拟机 WSL
内存 手动分配，独占（分配 4GB 就占 4GB） 动态共享，按需使用
CPU 手动指定核数 共享所有核心
启动速度 慢（要启动完整系统） 快（几秒进入）

为什么 WSL 不需要手动配置内存和 CPU？

虚拟机是独立操作系统实例，必须提前预留资源；WSL 则与 Windows 动态共享，用多少占多少，不用就释放。

1.2 适用场景

场景 推荐方案
日常开发、命令行工具、VSCode 远程开发 WSL
需要完整 Linux 图形界面、做内核实验 虚拟机

结论：日常开发用 WSL，需要完整图形环境才开虚拟机。

2 你现在在哪：理解 Linux 文件系统

进了 WSL 后，第一个困惑往往是：「我在哪？为什么没有 C 盘 D 盘？」

2.1 Linux 的目录结构

Linux 没有「盘符」概念，所有文件都在一个根目录 / 下：

目录 作用
/home 用户家目录（你的个人文件放在这）
/etc 系统配置文件
/var 系统运行产生的数据（日志、缓存等）
/tmp 临时文件，重启后清空

你的用户家目录是 /home/你的用户名，简写为 ~。

2.2 WSL 的特殊性：访问 Windows 文件

Windows 的磁盘被挂载在 /mnt/ 下：

  • /mnt/c/ → Windows 的 C 盘
  • /mnt/d/ → Windows 的 D 盘

例如 /mnt/d/projects 就是 Windows 的 D:\projects。

关键认知：你在 Linux 里，但可以访问 Windows 文件。跨系统访问性能会打折，详见第 5 节。

3 为什么需要用户和权限

Windows 也有管理员，为什么 Linux 这么强调权限？

3.1 root 是什么

root 是 Linux 的超级管理员，权限最高：

  • 能修改任何文件，包括系统核心配置
  • 能删除整个系统（真的能删库跑路）

正因为权限太大，日常操作不建议用 root。

3.2 sudo 是什么

sudo = “SuperUser DO”，临时借用 root 权限执行单条命令。

执行时会让你输入密码（就是创建用户时设的那个）。

实用建议：

  • 日常用普通用户登录
  • 需要管理员权限时加 `su
  • do`
  • 别一直用 root，容易误操作

4 软件包管理的正确使用

4.1 Windows vs Linux 的安装方式

Windows Linux
下载 .exe / .msi 双击安装 apt install 软件名
自己找官网下载 统一的软件源（仓库）
手动处理依赖 自动处理依赖关系

「软件源」就像一个官方维护的仓库，里面存着各种软件包。你不用到处找下载链接，直接从仓库拉。

4.2 apt 常用命令

命令 作用 使用频率
apt update 更新软件源列表（刷新仓库目录） 经常
apt install 软件名 安装软件 按需
apt search 关键词 搜索可用软件 按需
apt remove 软件名 卸载软件 按需
apt upgrade 升级所有已安装软件 ⚠️ 谨慎

4.3 ⚠️ 关于 apt upgrade 的重要警告

apt update 只是更新「软件源列表」（刷新目录），不会改动已安装的软件，可以经常跑。

apt upgrade 会把所有已安装软件升级到最新版，实际开发中要谨慎使用：

  • 如果项目依赖特定版本（如 Python 3.10），随意升级可能导致版本冲突
  • 生产环境/开发环境：先确认依赖兼容性再升级
  • 版本管理应使用专门工具（如 pyenv 管理 Python、nvm 管理 Node.js）

建议：日常开发只用 apt update + apt install，不要习惯性 apt upgrade。

5 文件该放哪里：WSL 的性能边界

这是 WSL 特有的问题，虚拟机不存在这个困扰。

5.1 跨文件系统的性能差异

文件位置 Linux 工具处理 Windows 工具处理
WSL 内部（~/projects） 快 慢（需通过 /mnt/ 访问）
Windows 盘（/mnt/d/） 慢 快

原因：WSL 和 Windows 是两个文件系统，跨系统访问需要额外转换开销。

5.2 实际建议

  • 用 VSCode + WSL 远程开发：项目放 WSL 内部（~/projects）
  • 用 Windows 工具处理（如 Windows 编辑器）：放 Windows 盘
  • 避免「跨系统编译」：在 /mnt/d 里跑 Linux 的 gcc、npm，性能明显下降

6 实用技巧

以下技巧能显著提升日常效率：

技巧 作用
Tab 自动补全 打一半命令或路径，按 Tab 自动补全
Ctrl+C 强制终止当前命令（卡住时用）
上/下箭头 翻历史命令，不用重复输入
命令 --help 快速查看命令用法
man 命令 查看完整手册（按 q 退出）
